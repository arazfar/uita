# Architecture and modeling scope

Uita is a single-process modular monolith with a bounded experiment subprocess. FastAPI owns command validation and the revision API. Pydantic exports the shared OpenAPI contract. The domain does not import the UI, storage, or inference adapter. React/Vite/R3F renders server trajectories; the verifier never reads scene physics. This is a research simulator, not operational control.

`simulator.py` creates seeded demand, trajectories, injections, replay checkpoints and metrics. Coordinates are approximate local east/north NM; altitude is MSL feet; logical seconds reference 2026-10-17T16:00:00Z. Runway lengths follow FAA diagram cycle 2610; true bearings use an approximation. Gate and taxi geometry is synthetic. Arrivals outside the terminal are admission-controlled and hidden as pending; departure markers wait at gates. Routine replanning preserves admitted paths. Research pause freezes time. If an airborne arrival's runway closes, an explicit synthetic climb-and-exit diversion preserves its executed history and current position, then continues moving. It never counts as an arrival completion. New admissions wait through the escape horizon; affected unadmitted flights remain held until a verified new plan. The independent verifier checks escape trajectories against all actual motion. This is a hypothetical research contingency, not a published or certified go-around/diversion procedure; conflicting contingencies remain visible failures.

`planner.py` schedules a fixed ordering using OR-Tools CP-SAT. Optimality applies only within that ordering. All runways share a conservative reservation dependency; an additional synthetic taxi trunk is exclusive. There is no independent parallel arrival authority. A learned artifact may only select and order bounded optional observations. Each read consumes budget; eight are available per decision. Mandatory weather/freshness/route/priority facts and verification always run. Unseen optional readiness/occupancy uses conservative fallback bounds. Programs cannot authorize routes or alter objectives, physics, verification or safety thresholds.

`verifier.py` independently checks snapshot/rule/revision/expiry binding, mandatory observation freshness, complete coverage, route/closure, readiness, admitted commitments, runway occupancy, taxi trunk exclusivity, wake, emergency priority and broad performance limits. Above 1,000 ft MSL, overlapping piecewise-linear trajectories are clipped to vertical-separation applicability and analytical lateral closest approach is checked across that interval, detecting conflicts between ticks. The below-1,000-foot transition uses the runway resource; this is a research approximation, not an FAA procedure. Verdicts are pass/fail/unresolved. Commitment requires fresh independent verification.

`storage.py` uses SQLAlchemy JSON records with revision CAS and transactions. SQLite is local default; PostgreSQL uses the same schema through psycopg. Commands, versions, jobs, evidence and checkpoints persist. A commit and idempotency result are atomic. Reused keys with different commands fail. Replay reads the last checkpoint before the requested time; later disruptions cannot leak into earlier history. Interrupted jobs are marked at explicit API startup recovery, not when a reader opens storage. Run exactly one API worker: clock ownership and worker recovery do not use distributed leases. Schema v1 creates tables and records its version; future upgrades require explicit migrations. Target PostgreSQL/container validation is still required.

`learning.py` evaluates fixed development, validation and sealed final seeds with matched exogenous tapes. It advances, injects demand and gate-delay events, replans, verifies, commits passing pending reservations and counts executed completions. Rejected hypothetical plans cannot earn projected throughput. All flights/backlog count. Parent mutations and live candidates have identical observation budgets and fixed solver configuration. Immutable versions retain lineage, hashes and rejected results. Promotion requires all-case feasibility, 1% validation improvement over static and parent, at most 5% tail regression and cost limits. The final set is consumed only after selection freezes, then sealed. Every candidate may legitimately be rejected.

`provider.py` supports only account-discovered NVIDIA Nemotron on Crusoe. It verifies membership/capabilities/pricing, accepts strict observation-only JSON, caps input bytes/output tokens, and reserves aggregate spend in a persistent SQLite ledger. Ambiguous paid requests are not retried and retain their reservation. Keys stay server-side and are not logged. One live experiment obtains one parent-aware candidate and one fresh nonpersistent baseline from matched development evidence. Zero-call fixture mode remains available. The ledger must be shared if deployment topology changes.

Localhost is the default. Remote mutation requires `UITA_API_TOKEN`; Origin validation rejects foreign browser writes. Hosted deployment still needs TLS, secret delivery, authentication UX, backups, network restrictions and monitoring. No infrastructure was provisioned or deployed.

Metrics are research quantities. Scheduled delay and final-horizon completion are separate views. Fuel, CO2 and relative noise are proxy formulas, not aircraft-specific emissions, measured workload, decibels, CNEL or forecasts. Resequencing is fixed; there is no globally optimal traffic-control claim. No live NOTAM, flight, weather or navigation data is ingested.
