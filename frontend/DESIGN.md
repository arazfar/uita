# Uita frontend implementation notes

The canonical visual contract is [../DESIGN.md](../DESIGN.md). Read it before frontend design work. It replaces the earlier navy-and-cyan direction recorded here. The notes below describe existing implementation details, not target visual tokens.

Mode: Operate, with the 3D simulation as the primary inspection surface. The runway configuration and flight state are backend data; the environment is schematic.

Current fonts: locally served DM Sans Variable for interface and IBM Plex Mono for operational values. Use the root contract for target typography, size, and color decisions.

Composition: 70px identity/status header; full available 3D world with 332px operations inspector; 121px transport/reservations/replay strip; 29px research and connection status. Inspector tabs hold traffic, verified decisions, and bounded learning. Below 700px, world and inspector stack and the transport stays available in document flow. The scene has an accessible traffic table. Aircraft, runway, and camera controls are named buttons. Reduced-motion users receive immediate server-position updates and no CSS animation.

Geometry: one render unit is 1/2.8 NM horizontally. World x is east; world -z is north. Altitude is visually exaggerated (feet × .0009), explicitly not a separation measurement. SFO runway endpoints are rendered directly from the versioned backend pack. Shoreline, terminals, topography, and buildings are schematic. Aircraft are intentionally exaggerated for legibility. Rapier is limited to camera clearance against static terrain/terminal colliders. It has no role in flight safety or planning.

Assets: original Blender airliner at public/assets/uita-airliner.glb, generated by assets/source/create_assets.py with editable assets/source/uita-airliner.blend. Original meshes released under CC0. No downloaded aircraft geometry, textures, or logos. Fonts bundled via npm under SIL Open Font License. See assets/README.md.

Replay: main replay requests backend sampled checkpoints. Paired comparison uses the backend's matched states/trajectories, sampled at a single shared logical time. The UI interpolation does not replan or compute evaluation metrics. All summary metrics remain backend values and unavailable values are shown as an em dash.
